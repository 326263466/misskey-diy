# 站内虚拟币与红包

红包由独立的 `RedPacketService` 管理。用户确认发红包时扣除虚拟币并记录流水；发帖、私聊和聊天室仅通过 `redPacketId` 展示红包，不扣款，也不决定红包生命周期。普通帖子和聊天不需要钱包操作。

## 钱包

- 签到积分保留，按管理员设置的整数比例单向兑换虚拟币，默认 1:1。
- 钱包包含可用余额和未领取红包的预留余额。所有入账检查两者之和，保证退款不会因余额达到上限而失败。
- 兑换、管理员调整、发红包、领取和退款均写入流水。修改余额和写流水在同一事务内完成。
- 兑换和管理员调整使用请求 UUID 防止网络重试重复扣款。积分兑换与签到系统使用相同的用户行锁。
- 管理员增减余额时原因选填，最多 500 字；省略或留空不影响操作，已填写的原因保留在流水中。确认弹窗显示增减方向和金额，不显示用户名或原因。

## 红包生命周期

1. `red-packets/create` 创建红包，支持等额或拼手气，1–100 份，总额不超过 1,000,000，每份至少 1。有效期为 1、6 或 24 小时。
2. `coverId` 可选 `classic`（默认）、`lucky`、`sunset`。封面只影响显示。
3. 同一用户使用相同请求 UUID 和参数重试，返回原红包，不再扣款；更换参数会被拒绝。
4. 红包自身包含领取范围：公开给本站用户、指定用户，或指定群。私聊指定单个收款人；群聊使用 `audience: room` 和 `roomId`，不保存发送时的成员快照。只有群主也能发红包，后来加入的成员可领，但领取时必须仍在群内；群主也计入最多 50 人的群容量。
5. 用户取消编辑草稿时尚未扣款。确认发送后，红包进入独立的发出／收到记录；删除展示红包的帖子或消息不撤回红包，也不退款。领取人可从红包记录重新进入。发包者不能领取自己的红包。
6. 同一用户只能领取一次。重复请求返回原领取结果；拼手气算法为剩余每份保留至少 1 币。
7. 默认 24 小时后退回未领取金额。创建者账户删除时结清其未领取红包；已经领取的金额保留。资金流水不随宿主消息删除。
8. 单人红包等待收款人领取；打赏使用同一钱包和记录能力，在确认发送时直接入账。自定义祝福语会保留，未填写时界面展示默认祝福。
9. 点击帖子或消息中的红包打开领取弹窗；领取结果和记录也在弹窗中显示，不撑开消息。群红包在退群、群归档或删除后不可领取，未领取金额仍按到期规则退款；发送者可以查看记录。

## 接口与入口

- `red-packets/create`、`list`、`show`、`claim` 是独立接口；涉及红包的操作仅允许站内登录凭据。
- `notes/create`、`chat/messages/create-to-user`、`chat/messages/create-to-room` 使用可选的 `redPacketId` 发送已创建的红包。
- 钱包位于 `/settings/wallet`，管理员设置位于 `/admin/wallet`。
- 不提供法币充值、提现或积分反向兑换。

## 一致性与查询

群成员领取时按“群 → 成员 → 红包 → 按用户 ID 排序的钱包”顺序加锁，成员资格检查保持到事务结束，并与删除群的锁顺序一致。其他红包及退款按“红包 → 钱包”顺序加锁。数据库唯一约束保证请求 UUID 和领取记录不重复。帖子和消息展示不参与资金事务。

帖子和聊天列表批量读取红包摘要，避免逐条查询。创建者列表与收款人列表分别使用复合索引分页；过期任务使用状态与到期时间索引，启动时补扫，之后每分钟分批处理。服务重启不会丢失到期退款。

部署前需运行新迁移。数据库测试必须使用独立测试库，并检查编译后的配置确实指向测试库。
