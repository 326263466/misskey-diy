# 聊天与红包交互验收（2026-10-02）

本次实现：Boost 无回应时放在分享旁，有回应时移到内容末尾；红包帖子隐藏本地图标；红包卡片打开领取和详情弹窗；消息右键菜单只在气泡内触发；对方气泡适配主题；回应变化保持阅读位置。

群容量为 50 人，包含群主。只有群主也能发送群红包；后来加入的成员可领，领取时必须仍在群内。群红包使用动态群权限，原有公开红包和指定收款人红包保留各自领取范围。

- PASS：57 项浏览器测试，覆盖私信/群聊、明暗主题、320px/720px 宽度、回应增删后的可见消息位置、新消息跟随、右键边界、单人群发红包、领取弹窗与 50 条领取记录滚动。
- PASS：60 项前端专项单测，覆盖 Boost 入口、移动锚点、草稿保留、红包领取与失败恢复、群红包创建范围、聊天状态。
- PASS：12 项后端单测，覆盖 50 人边界、重复邀请、已入群用户、空成员查询缓存和实时订阅撤权竞态。
- PASS：后端源码 TypeScript 检查、后端构建、`pnpm build-misskey-js-with-types`、本轮文件 ESLint、SPDX。
- 未验证：测试数据库 `127.0.0.1:54312` 拒绝连接，11 项数据库测试没有执行；`pnpm --filter backend check-migrations` 同样未完成。不能据此认定数据库并发和迁移验收已通过。
- BASELINE：完整红包单测中 10 项封面上传测试失败，当前编辑器已由并行工作移除上传入口；本轮未恢复该入口。全前端类型检查还有现有测试及其他文件错误。

## 部署和人工复测

先在测试环境应用新增迁移 `1790909745748-RedPacketRoomAudience.js`，运行群容量、红包数据库测试和迁移检查，再部署。

1. 建立仅有群主的群，发红包；另一个账号加入后可以领取，退出后不能领取。
2. 群主加 49 名成员达到 50 人，同时接受最后名额的两个邀请应只有一个成功。
3. 在私信和群聊中向上查看历史消息，再添加/撤回回应，阅读位置应保持不变。
4. 右键消息文字可打开消息菜单；右键回应、时间、空白区域不能打开消息菜单。
5. 点击红包在弹窗中领取，重复点击不会重复领取；进入钱包后弹窗关闭。
6. 无 Boost 的帖子在分享旁显示入口；打开输入框后，另一个账号发送首个 Boost，入口和输入框随位置更新，草稿保留。
